# Pi 认知平面与自进化治理规格 v1.0

## 地位

本规格是 86 号提案的可执行治理真值。北极星定义方向，路线图定义阶段和退出条件，本规格定义 Pi 认知自更新与能力自改的准入门、审计边界和角色责任。

用户已确认：

- Pi 是已运行在 ECS 的中央协调者；
- 用户是唯一战略授权源、T3 决策者和最终裁判；
- Pi 不建立 Mac 本地代码 clone；
- Aetheris 是 Pi 的思维平面；
- CSM 产品功能冻结；
- 统一 Trae 承接原 Trae 与 Solo；
- ZCode 是非终端评审、分析、反哺和兜底角色。

## 已运行基线

当前已存在的基础闭环：

```text
每 4 小时采集信息
→ reflectOnExplore 反思
→ memoryProvider 持久化
→ embedding 语义检索
→ 日报展示
```

“闭环已运行”不等于“Pi 可以无门槛修改自己的能力”。基础认知闭环、认知自更新晋级和能力自改是三个不同层级。

## 角色责任

| 角色 | 责任 |
|---|---|
| 用户 | 战略、T3、客户承诺、最终满意度和能力自改最终批准 |
| Pi | 中央协调、意图理解、路由、结果收敛、认知闭环 |
| Trae | 实现、集成、Git/PR/CI、产品测试、浏览器验收 |
| ZCode | 非终端评审、根因分析、知识反哺、风险兜底 |
| Qoder | 设计资产、前端设计和受派实现 |
| Kimi | 终端实现、文件数据处理和飞书协同 |
| Mira | 架构、治理、公共记忆和真源维护 |

Pi 的协调权来自用户授权，不包含 T3 决策、生产部署、密钥操作、删除或计费。

## Aetheris 思维平面

Aetheris 负责外显 Pi 的认知和反馈闭环：

- 文字日记；
- HTML 活看板；
- 提案与决策选项；
- 观察、假设、已确认三级分级；
- 按用户、能力、领域、关系等主题组织反思；
- 接收用户反馈并进入下一轮认知处理。

Aetheris 不再以 CSM 产品为当前主线。历史 CSM 代码、数据和证据保留，解冻必须由用户另行裁定。

## 认知自更新质量门

Pi 可以提出认知更新，但进入“已确认”前必须满足：

1. **来源**：记录观察来源、时间和上下文。
2. **分级**：明确是观察、假设还是已确认。
3. **证据**：至少给出支持证据；存在反证时同时记录。
4. **置信度**：不得把低置信假设写成用户稳定事实。
5. **影响**：说明认知更新会影响哪些建议、路由或行为。
6. **反馈**：用户否定后必须保留纠正记录，不得静默覆盖。
7. **敏感边界**：不得把 secrets、私密原文或无必要个人信息写入公共治理仓。

晋级权限：

- 观察 → 假设：Pi 可执行；
- 假设 → 已确认：需要用户明确反馈，或满足已批准的多证据确认规则；
- 涉及战略、T3、客户承诺和身份属性：始终需要用户确认。

分级对应行为权限：

| 分级 | 允许行为 | 禁止行为 |
|---|---|---|
| 观察 | 记录、聚合、展示、请求补充信息 | 改变稳定路由、替用户下判断、触发外部动作 |
| 假设 | 提问、搜集反证、生成备选建议、请求用户确认 | 写入稳定用户画像、改变长期策略、触发 T3 或生产动作 |
| 已确认 | 在确认范围内影响建议、路由和低风险行为 | 超出确认范围泛化；绕过质量门改变能力 |

任何认知更新从高等级降回低等级时，相关自动行为必须同步停止。

## 能力自改质量门

Pi 可以生成能力提案，不能直接绕过亲属矩阵修改生产能力。

每个提案必须包含：

- 当前问题和触发证据；
- 预期收益；
- 影响范围；
- 变更文件或组件；
- 测试与验收标准；
- 回滚方案；
- 风险等级；
- 推荐执行 owner；
- 独立评审 owner。

效果准入字段：

- `metric`：至少一个与提案目标直接相关的可观测指标；
- `baseline`：变更前基线值、样本范围和采集时间；
- `target`：晋级阈值；
- `guardrail`：不得恶化的安全、质量或成本指标；
- `evaluation_window`：最短观测窗口；
- `evaluator`：不得由提案生成者单独担任；
- `failure_action`：未达阈值时回滚、降级或停止。

没有基线数据的能力提案只能进入实验环境，不能晋级为稳定能力。

准入流程：

```text
Pi 提案
→ ZCode/Qoder/Mira 按领域评审
→ Trae/Kimi/Qoder 在隔离分支实现
→ 自动测试和产品验收
→ 用户批准高风险或 T3 变更
→ PR 合并
→ 运行观测
→ 结果反哺记忆
```

Pi 不得直接：

- 修改审计通道；
- 关闭质量门；
- 提升自身权限；
- 读取或写入未授权 secrets；
- 执行生产部署、删除、计费或数据库破坏性操作；
- 直接 push 受保护分支；
- 将失败结果包装成成功。

能力晋级判定：

1. 所有功能测试通过；
2. 独立 evaluator 确认指标采集有效；
3. `metric >= target`；
4. guardrail 无退化；
5. 回滚经过验证；
6. 高风险或 T3 变更取得用户批准。

任何一项不满足即判失败，执行 `failure_action`，不得以“部分成功”绕过。

## 审计通道

原始审计记录永久排除出 Pi 自改白名单。

审计至少记录：

- 提案 ID；
- 输入证据摘要；
- 认知或能力变更；
- 评审结论；
- 用户裁定；
- 实现 commit/PR；
- 测试结果；
- 部署或生效状态；
- 回滚记录。

Pi 可以读取审计结果用于反思，不能修改或删除原始记录。

## 当前批准边界

已批准：

- 现有采集、反思、记忆和日报闭环继续运行；
- Pi 作为中央协调者；
- 认知更新按本规格分级；
- 能力提案进入独立质量门；
- Aetheris 思维平面方向；
- CSM 冻结。

未自动批准：

- Pi 绕过 PR 直接改能力；
- Pi 修改审计和质量门；
- Pi 获得 T3 权限；
- 生产环境变更；
- CSM 解冻；
- 新 secrets 或外部服务授权。

## 降级与停止

出现以下情况时停止自动晋级，保留基础只读闭环：

- 审计不可用；
- 质量门不可用；
- 输出无法区分观察、假设和已确认；
- 连续产生无证据认知；
- 能力变更无法回滚；
- 用户触发紧急停止；
- 漂移检测表明运行真值与 Git 真值不一致。
