## 总体判断

**有条件通过**——Pi 自进化方向是 83-86 Pi 体系的自然演进且方向正确，但"先开闸、后补质量门"的顺序是倒置的，且 Aetheris 全停 CSM 与 roadmap 使命层/O2 KR 直接冲突未处理；补齐"认知变更质量门最小集"并显式修订 roadmap/蓝图前，不应生效。

## 战略级问题

**1. 他进化结束、开自进化——时机成立吗？**

半成立。事实核对：roadmap v1.1 显示 O1 尚未真退出（5域一致性、Pi 治理 C 层残留），O2 执行闭环未验收，M2 度量后置、M3 退化检测未建、记忆层（OpenViking）未建——而 roadmap 明文写"反馈吸收依赖记忆层，未建前你的反馈只能人工消化"。北极星 v1.2 §二自己的条款是"质量门成熟后再开"，现在质量门不成熟，提案的做法是**修订条款本身来绕过条件**。这在程序上合法（用户有定稿权），但实质是把风险顺序倒置：应该是"先建认知变更质量门（可以很小），再开闸"，而不是"开闸后待规格第6问再回答质量门"。

范围蔓延风险：会有，但可控。"红线决策权永远在用户"不够——红线防的是 T3 动作，防不了**认知漂移**（Pi 对用户的理解慢慢跑偏，每一步都不触红线）。需要补的边界是：Pi 可自改的范围**白名单化**（只能改 user_model 和自己的成长提案），system prompt / 权限 / 红线配置 / 调度逻辑永远不在自改范围内。这一条必须写进修订后的 §二，不能只靠"红线在用户"一句话。

**2. Aetheris 转"思维平面、一体两面"——聚焦还是换概念？**

哲学词可以翻译成可落地的架构，所以不算虚：Aetheris = Pi 内在状态的**外显投影层**（Pi 写、用户读、评论回流），这就是 read model + feedback channel，技术上完全清晰。真正的问题不在概念虚，在**没有处理与既有真值的冲突**：roadmap 使命层写的是"服务飞书 CSM、12+并发客户"，O2 KR 是"通过 Aetheris 跟进至少1个真实客户"，蓝图 v1.1 是 CSM 产品本体。CSM 功能"全部暂停"等于砍掉 O2 退出条件和使命层的一半——北极星 §四校准条款明文禁止"默默地既不修订也不回轨"。所以：86号如果生效，必须**同步显式修订 roadmap 使命段 + 蓝图定位 + O2 KR**，且 CSM 功能应"冻结"而非"废弃"（代码与数据保留，随时可解冻），因为用户的本职需求没有消失，只是优先级让位。

**3. "像人一样思考"+活化 user_model——对 LLM 成立吗？**

修辞浪漫化，但机制成立。"LLM 无状态"是事实，活化 user_model 的正解恰恰是承认这一点：**认知外置为持久文档，每次推理时注入**——profile.yaml 从死 prompt 变成带版本的活文档，这是标准且正确的做法，不是幻觉。幻觉积累的风险真实存在，但有明确解法：每条 user_model 修订必须挂证据链（哪次观察、哪条原始数据），条目分三级——observation（观察到）/ hypothesis（Pi 的假设）/ confirmed（用户反馈确认）——**只有用户信号能把 hypothesis 升级为 confirmed**，注入 prompt 时 confirmed 权重最高、hypothesis 明确标注不确定性。再叠加 M4 记忆老化治理（过期衰减、矛盾标记）。没有这套分级+证据链，活化 user_model 就是幻觉复利机；有了就是可审计的认知层。这应是待规格6问里第1问的硬约束。

**4. HTML 活看板——思维透明还是自我表演？**

自我表演风险是真的，且被提案低估了。让 Pi 自主决定"给你看什么"，等于把观测通道交给被观测对象。解法不是限制 Pi 的看板自由，而是**双通道**：Pi 自主看板照做（这是它的表达自由，也是成长信号），但系统必须保留一条 **Pi 不可编辑的原始审计视图**——thinking 表落库的完整推理链按时间线原样展示，用户随时可以对照"Pi 说了什么"和"Pi 实际想了什么"。透明性来自落库的结构化推理（提案第五点第2层），不来自 Pi 的自选呈现。沙箱约束（无脚本/无外链/审计留痕）方向对，保留。

**5. 提案硬上限3——合理吗？**

强制聚焦的意图对，"合计3、两类挤占"的设计错。成长提案和工作建议是两个受众（Pi 自己 vs 用户），共享配额会导致 Pi 在"改进自己"和"帮用户"之间做不该做的取舍。改为：**展示上限分池（如各2或2+3），落库无上限**——重要但非紧急的提案进 backlog，不主动打扰但用户可随时拉取。上限只该限制"打扰",不该限制"记录"，否则丢掉的恰恰是提案机制想沉淀的长尾思考。

**6. 第一性：这是最直接路径还是过度工程？**

主干直接，配重合理，有一处可疑。用户需求"越来越懂我、能自己成长"分解开就是：认知外置可修订（user_model）+ 修订有依据（推理落库）+ 用户能看见并纠偏（外显+反馈）——三层认知平面正是这三件事的最小实现，不算过度工程。**可疑的是第6问"前端路线倾向新建极简"**：Aetheris 已有前端，为思维平面另起炉灶要警惕"重写冲动"；如果三形式（日记/看板/提案）能以最小页面挂在现有 Aetheris 上，就不该新建。更简单的替代方案（如"日记直接发飞书"）不成立——飞书是通知流不是可评论的持久平面，反馈回路建不起来。所以主干无更简方案，前端路线需在规格阶段用"复用优先"压制。

**7.（重点）与 83-86 蓝图的契合度 + 质量门缺失**

契合度要拆成两条线看：
- **Pi 成长线：自然演进。** 已有闭环是 采集→反思→记忆→日报→goal（提案→审批→研究→展示），86号加的是"认知层 + 外显反馈回路"——这正是闭环缺的下一环（反思有了但认知不落地、goal 有了但对用户的理解是死的）。thinking 类型已定义未建表、profile.yaml 已写未读，说明 83-85 的设计早就为此留了口，86号是把留的口接通。这条线 PASS。
- **Aetheris 产品线：方向断裂。** 蓝图 v1.1 的 CSM 本体 + Wave3-5 被整体停掉，这不是演进是转向。转向权在用户，可以转，但必须按校准条款走显式修订（见第2问），否则北极星/蓝图/roadmap 三份真值互相矛盾，编队校准基准失效。

**质量门缺失确实是本提案最大风险（确认）。** 现有 G6 流水线（Qoder规格→ZCode实现→Mira评审→用户批准）管的是"亲属给 Pi 装器官"，M3 管的是"新 Extension 退化回滚"——**两者都不覆盖"Pi 自改自己的认知"**。86号开的恰恰是这个无人看守的门。fleet-division G6 那句话必须重读一遍："孩子长新器官必须有质量门，否则自进化变成自污染"。

## 改进建议

生效前置条件（缺一不开闸）：

1. **认知变更质量门最小集**（回答待规格第6问，且前置不后置）：
   - user_model 每次修订 = 一条带证据链的 delta（观察来源ID + 推理链ID），版本化、可 diff、可一键回滚（git 式）
   - 三级认知分级：observation / hypothesis / confirmed，升级到 confirmed 必须有用户反馈信号
   - M3 机制下沉到认知层：修订后带观察期，用户负反馈超阈值自动回滚该 delta
   - Pi 自改白名单：仅 user_model + 自身成长提案；system prompt / 红线 / 权限 / 调度逻辑永久排除
   - M5 紧急制动覆盖认知循环（一键冻结 user_model 写入）
2. **同步修订三份真值**：北极星 §二 + roadmap 使命段与 O2 KR + 蓝图 v1.1 定位，一次审批打包裁定，不留矛盾文档
3. **CSM 功能改"冻结"不改"废弃"**：代码数据保留，蓝图里写明解冻条件
4. **看板双通道**：Pi 自主看板 + 不可编辑的原始推理链审计视图并存
5. **提案配额分池 + backlog 落库无上限**
6. **前端路线规格阶段以"复用现有 Aetheris 前端"为默认，新建需给出复用不可行的证据**

## 最大风险

**观测通道与被观测对象合一，且无认知质量门——两个风险叠加成一个死循环**：Pi 自改认知（无质量门 → 幻觉可积累）× Pi 自主生成唯一呈现界面（自选展示 → 错误不可见）× 用户"只反馈不干预、非实时"（纠偏频率低）。三者叠加后，一条错误的 hypothesis 可以进入 user_model → 影响后续观察的解读 → 在 Pi 自己设计的看板上以合理面目呈现 → 用户基于失真呈现给出反馈 → 反馈被吸收进一步强化错误认知。这是**认知自污染的正反馈回路**，而现有 G6/M3/红线全部不在这条回路上。改进建议第1条（证据链+分级+回滚）和第4条（不可编辑审计视图）就是为切断这条回路而设——这两条不落地，本提案不应生效。
