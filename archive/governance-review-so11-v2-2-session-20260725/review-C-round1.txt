## 本质问题回答

### Q1【架构契合度】

两层记忆不在同一抽象层：Aetheris 存的是编队级事实（matter/task/decision/knowledge + 审计），Mira session 是单平台 LLM 上下文的句柄，本身不冲突。真正的重叠发生在 review-sessions-index.yaml——它同时承担"评审审计记录"（归档性质，归 git 合理）和"运行时调度状态"（hook 据此 deny，本质是 task 运行时状态，按蓝图归 Aetheris）。当前阶段（O1/O2，Mira 经 ZCode 接入）留在 hook 层是务实的过渡，但架构真值 §4.4 已锁定 Mira 终局由 Pi 调度——届时 .zcode hook 对 Pi 的调度路径**零覆盖**，机制自动失效。结论：短期留 ZCode hook 可以，但必须登记为过渡态 + 迁移债务（运行时 session 状态最终归 Aetheris，执法逻辑随 Mira 调度权移交 Pi Extension）。

### Q2【编队一致性】

是过度承诺，且比表面更严重：不只是 C 豁免，而是**执法点只存在于 ZCode 的 hook 链**——Kimi/Trae/Pi 根本不加载 .zcode hooks，"所有协作矩阵遵循"目前实际是"ZCode 调度 Mira A/B 时被强制"。表述应改为能力驱动契约："凡调度支持会话续接的评审平台（当前仅 Mira -r），调度方必须续接；不支持的平台以 prompt 内嵌上轮结论作上下文补偿"。这样 C 例外从"豁免"变成"替代实现"——因为准则的真实目标是上下文连续（北极星终局第 4 条），-r 只是手段之一，豁免手段不该豁免目标。

### Q3【循环闭合】

自举风险的真实形态不是"round1 被误拦"，而是更危险的静默失败：兜底扫描扫到别的项目 → 查到别项目的 roundN-1 session_id → hook 强制 `-r` 到**错误会话** → 上下文污染，比 deny 更糟（deny 可见，污染不可见）。解法就是消灭推断：项目和 round 全部显式传入（环境变量），hook 只校验不猜测——自举路径随之简化为"评审调度时显式设变量"。蓝图里可借鉴的元治理模式有两个：节点 3 纪律（治理机制变更本身另起任务 + 独立评审，hook 不豁免自己）和 roadmap §8.4 pre-commit 正面案例（Pi B 层 round3）——本次评审走三方 round 流程本身就是对该模式的正确执行。

### Q4【真值层边界】

区分双重身份后判断清晰：session_id 作为**审计证据**写进 archive/（哪轮用了哪个会话）与现有评审证据归档惯例一致，不污染真值层；作为**运行时控制状态**被 hook 读取并驱动 deny 才是问题——它易变、会过期，而真值层语义是稳定事实。最尖锐的缺口：spec 没有 session 过期的降级通道。Mira session 失效后 `-r` 必然失败，但 hook 仍强制 `-r`，唯一出口 ARCHIVED 语义不符（项目没 PASS）——这是一条会硬卡死评审流程的死路。长期归宿同 Q1：运行时状态入 Aetheris，git 只留归档快照。

### Q5【与 A/B 共识的差异】

同意 A-M1 和 B-必修1，且我给 A-M1 更强的理由：兜底扫描的最坏失败模式是续接错误会话（静默污染），fail-closed 不只是原则问题而是唯一能消除该失败模式的方案。A-M3 方向对但需修正：要区分"显式 enabled:false"（M5 可制动性，放行）与"节点缺失/损坏"（异常，deny）——B-必修7 若不做此区分，会把紧急制动开关变成故障点。我认为 A/B 都漏了两个更架构级的问题：**执法点单一化**（Q2，spec 承诺与执法能力不匹配）和**session 过期死路**（Q4，机制自身会卡死自己服务的流程）。修复优先级：先修状态显式化（M1/M2 是正确性地基），同批修 spec 范围表述和过期通道（改文字成本低），Aetheris 迁移做债务登记不阻塞。
