## D2【识别逻辑漏洞】— **FAIL（含 1 个 BLOCKER）**

**BUG-1（BLOCKER）：`identify_current_round` 抓第一个 round**
```python
m = re.search(r'\bround[_\s]*(\d+)\b', command, re.IGNORECASE)
```
`re.search` 返回首个匹配。真实评审 prompt 极常见描述历史轮次（"round1 已修 → round2 复核"），会把当前轮识别为 `round1`，S2 的 "roundN 无 -r deny" 规则**直接被绕过**。

**修复建议**：
- 要求 prompt 采用受控标记，如 `[CURRENT_ROUND=2]`，hook 只认这个 tag；
- 或抓**最后一个** `round\d+`（`findall()[-1]`）——仍不严谨，但比首个好；
- 或强制约定"当前轮号"只出现在命令第一行 / 特定前缀后。

**BUG-2：`extract_resume_id` 对 `-r` 后无值静默返回 None**
```python
pat = re.compile(re.escape(resume_arg) + r'(?:=|\s+)(\S+)', re.IGNORECASE)
```
`mira -p "..." -r` 命令：regex 不匹配（`-r` 后是行尾或无 `\S+`），返回 `None`。roundN 场景下等价于"未续接" → deny，行为**恰好正确但纯属巧合**。若未来把"None 视为放行"的分支加入，会立刻出漏洞。建议**显式检测"有 -r 但无值"并 fail-closed 报错**，比隐式 deny 更安全。

**BUG-3：`find_current_project` 兜底返回 `None`**
archive 为空 → 返回 `None`。后续 hook 拿 `None` 去查 `review-sessions-index.yaml` 的 project 节点，行为未在代码片段中呈现。可能：
- 抛 KeyError（fail-closed，OK）；
- 或误认为"无历史轮次" → 首轮放行（漏洞，BLOCKER）。

**必须明示**：project=None 时 hook 的策略是 deny 还是 allow。当前不可知。

**BUG-4：`find_current_project` 的兜底扫描按 mtime 排序**
Windows 下 mtime 精度 & git checkout 会触碰 mtime，可能与"逻辑最新项目"不一致。评审并发时（同时改多个 governance-review-* 目录），会挑错项目。建议**兜底策略以显式索引文件为准**（`review-sessions-index.yaml` 里的 `current_project` 字段），mtime 扫描完全废弃。

## D4【数据一致性】— **CONDITIONAL**

**Windows 路径问题**：
`os.path.join(REPO_ROOT, "archive/review-sessions-index.yaml")` 在 Windows 上会产出 `C:\...\archive/review-sessions-index.yaml`（混合分隔符）。Python 的 `open()` 能吃，YAML 读取无问题；**但**：
- 如果 hook 把这个路径**回写到 yaml 里作为记录字段**，跨平台 diff 会不稳定；
- 如果传给外部工具（shell），bash.exe 下正斜杠 OK，cmd.exe 下混合会崩。

建议统一用 `pathlib.Path` + `.as_posix()` 存储、`str(Path(...))` 用于本地文件访问。

**跨平台一致性**：
hook 只在 ZCode（Windows）跑 → 只需 Windows OK。但 ECS/Linux CI 跑单测时，`os.path.join` 分隔符不同，测试 fixture 里若硬编码 `\\` 或 `/` 会跨平台失败。8/8 单测只在 Windows 跑过是不够的，**必须在 Linux CI 也跑一遍**再声明"验证通过"。

## D6【与现有 hook 共存】— **CONDITIONAL**

**性能影响**：
每次 Bash 调用都跑 4 个 hook（3 PreToolUse + 1 PostToolUse）。假设每个 hook 冷启动 Python 解释器 ~150ms（Windows），单次 Bash 多增 450-600ms。评审密集场景下（几十次调用）体感明显。建议：
- 合并同类 PreToolUse hook 为单个 dispatcher；
- 或用长驻进程（socket）+ 客户端脚本调用，避免重复冷启动。

**drift-gate 误判**：
`session_continuity` 是 reviewer-tiers.yaml 新加节点。drift-gate 若基于 schema 白名单校验，新字段会被视为漂移。**必须同步更新 drift-gate 的 schema 白名单**，否则 SO-11-v2-2 一合入就触发 drift 告警。

需检查 `.zcode/hooks/tiers-drift-gate.py` 的 schema 定义，本次改动是否已联动更新——commit 317d213 diff 里没提到，**列为 BLOCKER 候选**，请贴 diff 确认。
