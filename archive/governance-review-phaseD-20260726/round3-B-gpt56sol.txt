### 2.1 `redact-tokens.py` 出现 SyntaxError

`scripts/redact-tokens.py:25-27`：

```python
REPO = Path(__import__("os").environ.get(
    "REPO_ROOT",
    str(Path(__file__).resolve().parents[1]))
```

外层 `Path(` 没有闭合。实际编译结果：

> `SyntaxError: '(' was never closed`

因此声称完成切换的 6 个脚本中，`redact-tokens.py` 已完全不可运行。这是本提交直接引入的新阻断。

**建议修法**：

```python
import os

REPO = Path(
    os.environ.get(
        "REPO_ROOT",
        str(Path(__file__).resolve().parents[1]),
    )
)
```

修复后应至少执行：

```bash
python -m py_compile scripts/redact-tokens.py
```

### 2.2 `mirror-sync.py` 仍使用固定 checkout 路径

- `scripts/mirror-sync.py:234`：源目录仍固定为 `~/.agent-collaboration`。
- `scripts/mirror-sync.py:235`：目标仓库仍固定为 `~/Documents/trae_projects/agent-collaboration-standard`。

因此在其他 clone/checkout 中执行 dry-run 时，审计的仍可能是另一份固定 checkout，而不是当前被评审仓库。虽然 `--apply` 已禁用，破坏性写入风险被消除，但 **dry-run 的跨 checkout 混读问题仍存在**。

**建议修法**：让 `DST_ROOT` 使用与其他脚本一致的 `REPO_ROOT`/`__file__` 推导；旧快照源可单独提供环境变量，例如 `LEGACY_SNAPSHOT_ROOT`。

## 阻断 3：禁用 `mirror-sync --apply`

### ✅ 已修复

证据：

- `scripts/mirror-sync.py:288-292` 在参数解析后立即检测 `args.apply`，输出错误并 `return 1`。
- 实际执行 `python scripts/mirror-sync.py --apply` 返回 **exit code 1**。
- 错误信息明确说明：
  - 原方向是只读快照到 git 真值；
  - 该方向会覆盖 git 真值；
  - 如需反转方向必须另立规格和独立评审。
- dry-run 代码路径仍保留，且所有同步函数接收到的 `apply` 固定为 `False`。

本机独立环境没有 `~/.agent-collaboration`，所以 dry-run 按 fail-closed 设计返回 1；这不代表写盘路径重新开放。

**软观察**：

- `scripts/mirror-sync.py:278-279` 的 `--apply` help 仍写着“真正写盘”。
- `scripts/mirror-sync.py:350-353` 仍提示“加 `--apply` 重跑”并保留不可达的 apply 成功分支。

建议清除这些遗留提示，避免使用者误以为 `--apply` 仍受支持。
