## 核对二:`git grep --cached` 修订是否合理 ✅ 合理

- **核心机制正确**:`git grep --cached -l -F "$pattern"` 直接扫暂存区 blob(index),不读工作树,`-F` 字面匹配 + 内部处理文件名,彻底规避了 v3.1 `xargs grep` 的文件名空格/换行断裂问题。B.1 + C 备注成立地闭环。
- **配套断言到位**:patterns 有效性校验(`VALID_COUNT < 1` fail)、暂存区非空校验(`STAGED_COUNT=0` fail)均已补,patterns 空转假通过风险已堵。
- **顺序正确**:`git add .` 在扫描前,扫的是实际入库内容;命中即 `git reset` + `exit 1`,门禁语义闭合。

## 非阻断观察(不影响本轮结论,供节点2 参考)

patterns 文件示例行带行尾注释(如 `<anthropic-token-prefix>     # 例:8-12 字符前缀`)。当前过滤 `grep -vE '^\s*#|^\s*$|^\s*<'` 只剔除**行首** `#`,不剥离**行尾**内联注释。若用户填入真实前缀时保留了 `PREFIX  # 备注`,`git grep -F` 会把整行(含注释)当字面串检索,导致永不命中——安全门禁的**假阴性**。建议 patterns 提取时补一步 `sed 's/[[:space:]]*#.*//'` 去尾注,或在文件说明里硬性要求"一行仅一个纯值、禁带注释"。
