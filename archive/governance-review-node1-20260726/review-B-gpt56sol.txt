# 评审方 B：架构评审结论

## 一、5 个本质问题

### 1. 真值一致性

**当前方案尚未真正建立单一真值存储。** 同步完成后，git 仓库可以成为候选真值源，但 `~/.agent-collaboration/` 的最终处置仍留在 X/Y/Z 三选一阶段；其中 Z 明确继续维持双存储，不能满足北极星红线。

终局应只有 **1 个可写权威位置：git 仓库**。运行时可以有只读工作副本或兼容入口，但必须由 git commit 唯一标识版本、禁止反向写入；另外，X 方案不能直接使用，因为本地的 `standards/` 与仓库的 `governance/` 目录结构并不一致，整目录符号链接会破坏现有路径契约。

### 2. 冗余消除

**方案目前只完成了冗余盘点，没有完成冗余消除。** D1 把 `unified`、`workspace-collaboration`、`protocols` 等文档的去留推迟到后续阶段，而且预设“推测 unified 应为权威”，缺少逐条规则的来源、冲突和归属矩阵。

这可以作为治理计划的一部分，但不能据此宣称 O1 已实现“每条规则只有一份权威”。必须把“唯一规范、补充规范、历史归档、删除对象”转化为可验收的决策表，并由用户确认战略性去留。

### 3. 语义错误修正

**当前同步方案主要搬运文件，不会自动修正语义错误。** `unified` 中 Claude Code 等退役对象的引用会原样进入 git，甚至可能因为进入权威仓库而获得更强的错误权威性。

D1 虽然计划后续修正，但缺少退役实体词表、全仓引用扫描和“零有效引用”的验收标准。因此同步只能称为“抢救并纳管现状”，不能称为“完成语义一致性治理”。

### 4. 时序版本机制

**当前仍然依赖人工纪律，自动化机制尚未成立。** `/truth/versions` 只是后续设想，D3 也只是计划增加 hook；现有步骤没有 manifest、内容哈希、commit 对齐检查、CI 门禁或写入路径约束。

此外，本地 pre-merge hook 可被绕过，不能单独承担治理门禁。时序一致性至少应由仓库 CI 校验关键文档版本、退役引用、敏感信息及目录清单，并以 commit SHA 作为唯一版本身份。

### 5. 不可委托敬畏

**总体上识别了战略决策必须由用户裁决，但边界仍不够严密。** 文档去留设置了用户逐份确认，远程分支和目录删除也要求授权，方向正确。

不过，计划已经隐含选择了 local 覆盖 git、可能以 `unified` 为权威，以及“直接 push master”等架构和治理决定。评审方可以提出推荐方案，但这些决定应在执行前形成明确决策记录，由用户批准，而不能由同步脚本事实性地代替裁决。

## 二、架构级风险

1. **敏感文件误纳管风险极高**  
   Step 2 的循环会实际复制整个 `archive/`，包括明确要求“绝对不复制”的 `archive/cc-retirement-20260726/`；Step 3 才增加 `.gitignore`。即使最终未被 `git add`，明文密钥仍被复制进 git 工作区，而且 `.gitignore` 无法保护曾被跟踪的文件。

2. **声明的精确同步与实际命令不一致**  
   `cp ~/.agent-collaboration/templates/*.md templates/` 会覆盖同名模板，并非“只补齐”；`cp -r standards/* governance/` 只增量覆盖，不会处理目标侧陈旧文件，也不能证明镜像完整。脚本实现没有忠实表达方案语义。

3. **错误内容被提升为权威真值**  
   当前动作先同步、后治理语义和文档去留，可能把退役工具引用、重叠规则和错误归档一起正式推入 master。完成的是“存储集中”，不是“语义一致”。

4. **回滚与泄密处置模型不完整**  
   本地 tag 和 backup branch 若未推送，不能防本机故障；“force push 后轮换 token”顺序错误。任何可能进入提交或远程的密钥都应立即轮换，随后进行历史清理、远程缓存与派生副本检查，不能把 force push 当作彻底删除。

5. **评审机制缺少可执行门槛**  
   “三方一致通过”没有统一结论枚举、阻断项定义、证据要求、超时/缺席处理和修改后复审范围。节点 2 只写“人工审查”，缺少机器可验证的验收结果，容易形成流程很重但质量门禁仍靠主观判断的情况。

## 三、改进建议

1. **先建立安全的受控导入流程，再允许 commit**  
   使用显式白名单逐目录导入，而不是复制后用 `.gitignore` 排除；导入前检查工作区、符号链接、文件类型和敏感路径，导入后生成源/目标 manifest 与哈希差异，并执行 secret scan。将变更放入临时分支，通过评审后再合并，不直接 push master。

2. **把单一真值终局写成不可含糊的架构决策**  
   明确 git 仓库是唯一可写源，`~/.agent-collaboration/` 只能删除、改为结构兼容的入口，或由 commit 单向生成的只读副本；排除 Z。若保留旧路径，应建立逐路径映射，而不是把目录结构不同的仓库根直接做符号链接。

3. **增加可量化的阶段验收门禁**  
   阶段 1 应验收：零敏感文件、零非白名单覆盖、源文件全部可追溯、仓库原有内容无非预期删除；阶段 3 应验收：每条规则唯一归属、退役实体零有效引用、所有文档去留均有用户决策记录；长期机制应由 CI 校验 commit SHA、manifest、规则引用和 secret scan，而非只依赖人工或本地 hook。

## 四、是否通过

**结论：不通过。**

治理方向——以 git 为唯一真值、消除规则冗余、保留用户战略裁决权——是正确的；但当前执行方案存在**排除规则与复制命令直接矛盾、敏感信息误复制、目录结构不兼容、自动校验尚未落地**等阻断性问题。按现版本执行，既不能证明建立了单一真值，也可能造成密钥泄露或错误内容被正式确认为权威。

建议修订后重新提交节点 1 评审；在三方重新一致通过前，**不得执行 Step 2—5，也不得直接向 master 推送**。
