## 备注逐条核对

### 备注 1：Step 4 全文件扫描 — 部分解决，存在阻断性缺陷

扫描范围问题本身已修（去掉 include 限定、外部 patterns 文件、`grep -F` 字面匹配），方向正确。但修订后的实现有两个问题：

**1a（阻断）：执行顺序缺陷，扫描是空转。**
Step 4 核查 2 用 `git diff --cached --name-only` 取待扫文件，但 `git add .` 在 **Step 5** 才执行。Step 4 运行时暂存区为空 → 扫描零文件 → 永远通过。核查 4 的 `git diff --cached --stat` 同样全空。附带效应：xargs 空输入时 `grep -lF` 无文件参数会读 stdin，脚本可能挂起。

修法（二选一）：
- 把 `git add .` 前移到 Step 4 之前，Step 5 只做 commit；
- 或核查 2 改扫工作树（`git ls-files -o -m --exclude-standard` + tracked 文件）。
推荐前者，与门禁 #6（dry-run 与暂存区差异为 0）语义一致。

**1b（阻断）：方案文档仍含 token 片段，与修订声明矛盾。**
"§Step 4 patterns 文件"示例块中列出了 `[ANTHROPIC-REDACTED]`、`[ANYGEN-REDACTED]`、`[ZCODE-REDACTED]` 三个真实片段——其中第三个标注为 **ZCode 在用 token 前缀**。"脚本不含 token"成立，但本 spec 文档若入 git，等于把 A 的阻断换了个位置复现，且这次泄的是在用凭证前缀。修法：文档中该代码块只保留格式说明（"每行一个固定字符串，示例：`<token-prefix>`"），真实内容仅存在于本机外部文件。
