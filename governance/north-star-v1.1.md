# 北极星（North Star）v1.0 定稿

> 定稿: 用户（林于炜）裁定生效，2026-07-23 | 起草: Qoder
> 地位: **方向环 M1 唯一校准基准**。所有校准、回轨、进化质量门以本文档为比对基准
> 修订: 定稿权专属用户；任何智能体只可提议修订；每次修订产生新版本号并保留历史，防止目标被静默篡改

---

## 一、终局（唯一长期目标）

> **用户只需制定战略和确认关键决策，其余一切围绕设定轨道自动运转。**

（血统：继承自 Aetheris 蓝图终局定义，经用户在编队重构中反复确认，2026-07-23 定稿）

具体形态：
1. 用户在任何入口（飞书移动端为主）说一句话 → 编队理解意图、路由到对的智能体、完成任务、回报结果
2. 用户不说话 → 系统按轨道自动运转（漂移治理、任务推进、状态公示），不打扰
3. 重要动作（T3）才需要用户出现——且只是移动端一次审批点击
4. 跨会话、跨智能体连续——真值在 git 与 Aetheris，不依赖任何单一 agent 的记忆

## 二、孩子与亲属矩阵（实现路径）

- **Pi 是"孩子"**：中央协调智能体，常驻 ECS，由**亲属矩阵培养长大**
- **编队是"亲属"**：ZCode/Qoder/Kimi/Trae/Mira 各以所长反哺 Pi（写 Extensions、出规格、评审、测试）
- **现阶段是"他进化"**：亲属建设 Pi，不是 Pi 自进化；自进化能力等底座跑顺、质量门成熟后再开
- **用户只定目标，成长由矩阵负责**

## 三、不可动摇的边界（红线，凌驾一切进化）

1. 用户是唯一协调者与最终裁判；协调者地位不可被任何智能体自封或继承
2. 密钥主权在本地：T3 高权限密钥永不出本地守卫，移动端只做审批不载 key
3. git 真值不可绕过：agent 只在 `agent/<name>` 分支，master 变更必经集成窗口+审批
4. 一切自动化必须可审计、可制动（M5 紧急停机永远有效）
5. 进化不得以突破以上任何一条为代价——**违反红线的"能力提升"视为退化**

## 四、校准条款（方向环运行规则）

- 点状偏差：容忍并记录，不过度矫正（保护探索性）
- 趋势偏航：校准报告比对本文档 → 回轨提案 → 用户裁定
- 本文档与实际演进长期冲突时：要么修订北极星（用户定），要么回轨（用户定）——**绝不允许"默默地既不修订也不回轨"**

## 五、当前阶段目标（可随阶段更替，终局不变）

**把协作底座跑顺**：CC→ZCode 迁移 → Pi ECS 部署 → 漂移治理上线 → Qoder SSE 消费器 → 飞书桥接 → Mira/Kimi 接入。

**优化整体触点体验**：编队与用户的每一次交互（飞书卡片通知、审批按钮、状态展示、移动端入口）都必须让非程序员能直接理解和决策。具体标准：
- 用户看到的每一条信息，必须包含"这是什么、为什么发生、影响是什么、我该做什么"四要素
- 严禁向用户展示原始技术数据（文件路径、commit hash、diff）而不附人话解释
- 用户能做的决策必须在消息内提供操作按钮（不要求用户去别处找工具）
- 触点体验持续优化：每个版本迭代降低用户的认知负担，目标是"看一眼就懂、点一下就办"

## 六、触点模板基线（v1.0，2026-07-23 定版）

漂移告警交互卡片 v1.0 为首个触点模板，后续所有编队→用户的通知遵循此基线：

| 要素 | v1.0 标准 |
|------|----------|
| 标题 | 图标 + 类型名称（如"⚠️ Pi 漂移体检报告"） |
| 副标题 | 数量摘要 + 时间戳 |
| 正文 | 每个事项含：状态说明（人话）+ 冲突/详情（人话）+ 影响评估 + 最近工作摘要 |
| 底部总评 | 总体影响一句话总结（"X个可自动解决,Y个需人工,你不需要操作"） |
| 操作按钮 | 主操作(primary_filled) + 次操作(default)，按钮文字是人话不是技术术语 |
| 禁止 | 禁止向用户裸露文件路径/commit hash/diff 而不解释；禁止纯文本通知替代卡片 |

迭代规则：触点体验优化是长期目标，每个版本迭代都应降低用户认知负担。
