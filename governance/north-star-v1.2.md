## 一、终局（唯一长期目标）

> **用户只需制定战略和确认关键决策，其余一切围绕设定轨道自动运转。**

（血统：继承自 Aetheris 蓝图终局定义，经用户在编队重构中反复确认，2026-07-23 定稿）

具体形态：
1. 用户在任何入口（飞书移动端为主）说一句话 → 编队理解意图、路由到对的智能体、完成任务、回报结果
2. 用户不说话 → 系统按轨道自动运转（漂移治理、任务推进、状态公示），不打扰
3. 重要动作（T3）才需要用户出现——且只是移动端一次审批点击
4. 跨会话、跨智能体连续——真值在 git 与 Aetheris，不依赖任何单一 agent 的记忆

## 二、孩子与亲属矩阵（实现路径）

- **Pi 是"孩子"**：中央协调智能体，常驻 ECS，由**亲属矩阵培养长大**
- **编队是"亲属"**：ZCode/Qoder/Kimi/Trae/Mira 各以所长反哺 Pi（写 Extensions、出规格、评审、测试）
- **现阶段是"他进化"**：亲属建设 Pi，不是 Pi 自进化；自进化能力等底座跑顺、质量门成熟后再开
- **用户只定目标，成长由矩阵负责**

## 三、不可动摇的边界（红线，凌驾一切进化）

1. 用户是唯一协调者与最终裁判；协调者地位不可被任何智能体自封或继承
2. 密钥主权在本地：T3 高权限密钥永不出本地守卫，移动端只做审批不载 key
3. git 真值不可绕过：agent 只在 `agent/<name>` 分支，master 变更必经集成窗口+审批
4. 一切自动化必须可审计、可制动（M5 紧急停机永远有效）
5. 进化不得以突破以上任何一条为代价——**违反红线的"能力提升"视为退化**

## 四、校准条款（方向环运行规则）

- 点状偏差：容忍并记录，不过度矫正（保护探索性）
- 趋势偏航：校准报告比对本文档 → 回轨提案 → 用户裁定
- 本文档与实际演进长期冲突时：要么修订北极星（用户定），要么回轨（用户定）——**绝不允许"默默地既不修订也不回轨"**

## 五、第一性原则（立足宏观，找最大范围内的最优解）

以下原则凌驾于所有具体实现决策，是编队一切建设的思维基座：

1. **所有决策从问题本质出发，不因"惯例如此"照搬。** 回到问题本身：要解决什么？最直接的路径是什么？从零设计会怎么做？
2. **人机协同界面的质量是终局的决定性约束。** 系统能否达到"用户只定战略，其余自动运转"，取决于编队与用户之间的信息传递是否高效——用户能否在最小认知负担下理解状态、做出决策、传递意图。这不是 UI 细节，而是系统能力的核心维度：界面是连接"自动运转的机器世界"和"只关心结果的用户"的唯一桥梁。
3. **给用户看到的每一条信息，必须通过"非程序员能直接理解和决策"的检验。** 技术细节（文件路径、commit hash、diff）只在必要时作为证据附注，主体必须是"这是什么、为什么发生、影响是什么、我该做什么"的完整人话表述。
4. **持续优化不是点状修补，而是向"零认知负担"方向的系统性演进。** 每个迭代都应从"用户为什么还需要操心这个"出发，寻找消除该操心的根本方案，而非在现有交互上叠加更多说明。

## 六、当前阶段目标（可随阶段更替，终局不变）

**把协作底座跑顺**：CC→ZCode 迁移 → Pi ECS 部署 → 漂移治理上线 → Qoder SSE 消费器 → 飞书桥接 → Mira/Kimi 接入。
